# Frontend (React, Vite, Zustand, Tiptap 3)

Type-check with `npx tsc -b` (`tsc --noEmit -p .` checks nothing). Every API call is in
`src/api/` (one fetch wrapper in `client.ts`); shared types are in `src/types/`. Report a
failure with `toast.error` (`stores/toastStore`), never `window.alert`. Navigate from non-React
code with `lib/navigation.ts`, never `window.location`.

## Single-source lists

Add to the list; never hard-code a copy.

- **Story pages:** `lib/routes.ts` drives the logo menu, the palette and `ModeGate`. A grouped
  page declares `sections`, old paths go in `STORY_REDIRECTS`, bodies in `pages/routeElements.ts`.
  Every page but the prose uses `components/layout/PageHeader`.
- **Keyboard shortcuts:** `lib/keyboard/shortcuts.ts` (`matchesCombo`, `formatCombo`).
- **Settings sections:** `pages/settings/sections.ts`.
- **Guides:** `guides/index.ts`, one `.md` each.
- **Glossary:** `lib/glossary` holds every entry; `guides/glossary.md` draws a group at
  `<!-- terms:<group> -->`, and `components/common/Term` (or `{{term:id}}` in copy kept as data,
  drawn by `TermText`) shows one in a popover. `lib/glossary/curated.test.ts` fails when a
  listed craft word is shown in a file without its `Term`.
- **AI features:** `lib/ai/features.generated.ts`, generated by `just gen`.

`lib/commands/coverage.test.ts` fails when a route, section, shortcut or guide has no palette
command.

## Theme and look

- Tokens are in `src/themes/base.css`, plus one file per palette (`[data-theme="x"]` and `.dark`).
- `themes/contrast.test.ts` holds every palette to WCAG AA: change a token, run it.
- `src/reset.css` is the browser reset.
- A choice the author makes in Settings (theme, type, sizes, the notes margin, the strip's
  colours) is kept with `rememberPref` (`lib/preferences/accountPrefs.ts`) so it follows the
  account; add its key to `ACCOUNT_PREFS`. Window layout (widths, open tabs) stays in
  `localStorage`, per device.
- Layout and chrome rules (one ground, tone boxes over lines, button tiers, readability floors)
  are in `../DESIGN.md`.

## AI surfaces (Studio mode only)

- **Icons, always with a text label:**
  - `Feather`: open a conversation.
  - `Orbit`: a one-shot action.
  - `Square` with "Cancel": while it streams.
  - `Wand2`: suggest a field.
  - Never `Sparkles` (ESLint blocks it); `Compass` means Guides.
- **Button:** `--color-ai` with `--color-ai-fg`, as `.generateBtn` in
  `components/story/StorySummaryPanel.module.css`.
- **Required pieces:**
  - an `AIFeatureInfoTrigger` (`Cpu`) in the header of any panel or page with AI;
  - an `LLMTransparencyTrigger` (`ShieldCheck`, `useLLMTransparency`) beside AI output.
- **Placement:**
  - On a Lorebook or Promises sheet, actions are the header's "Assistant ▾" menu (`EntitySheet`'s
    `assistant` slot; `lib/ai/sheetActions.ts`), each item a registry row's label and
    `shortDescription`. One-shot answers are kept on the server (`assistant_results`, written by
    the route with `assistant_results.keep`, or `keep_text` as a stream's `on_complete`) and
    shown in the tone-box band under the header (`components/lorebook/assistant/`): Talk it
    over, Ask again, Clear, Fold away.
  - Anywhere else a one-shot answer is kept the same way on what it is about (a scene is
    "node", an image, an outline, or "story") and shown where it was asked for:
    `useKeptAnswer(subject, feature)` and `KeptAnswerBar` (`components/ai/kept/`). Opening a
    surface shows the kept answer; it runs only on Ask again, or when nothing is kept.
  - On a Plan step, its one `AssistantRow`.
  - On a page they live in the header's ⋯ menu, never as buttons across the page.
- **The Assistant:** every conversation lives in the side panel's Assistant, opened from the
  rail's Feather, ⌘J or the palette (`components/ai/AssistantTabBody.tsx`).
  - Add a session type in `lib/ai/sessionTypes.ts` and `components/ai/SessionView.tsx`, with
    `AIModeWrapper` as its shell.
  - A new feature's surface goes in `lib/ai/registry/<page>.ts`, under its `pageId` in
    `featureRegistry.ts`.

## The editor and undo

- `components/editor/SceneEditor.tsx` is a shell over hooks (`useSceneAutosave`,
  `useMentionDropdown`, `useSlashCommands`, `useInlineNotes`, …) with `EditorTopbar` (its ⋯ is
  `EditorMoreMenu`) and `StatusCorner` (the save light and word count).
- StarterKit comes from `editor/starterKit.ts`.
- Autosave sends `expected_updated_at`; a 409 offers Keep mine / Take theirs. Drafts are mirrored
  to IndexedDB (`lib/draftBuffer.ts`).
- **One undo timeline:** `stores/undoStore.ts` merges the open scene's typing
  (`lib/undo/sceneHistory.ts`, `UnifiedUndoExtension`) with server changes.
  - Text arriving from outside never enters the editor's history: use `loadScene` or
    `patchScene`, never `editor.commands.setContent`.
  - A component that keeps its own copy reloads through `useReloadOnUndo`.
- **Jobs:** one poller, `stores/jobsStore.ts`. Pages use `useJobs` / `useOnJobFinished`; the
  header's `JobsIndicator` lists them.

## Where things are

- `components/layout/`: the header, `LogoMenu`, `StoryCrumbs`.
- `strip/`: the story strip on the left.
- `panel/`: the side panel. The rail launches This scene, the tools and the Assistant; tabs hold
  what you opened.
- `scene/` with `pages/SceneSheetPage`: the Scene sheet.
- Every other folder in `components/` is named for its page or domain.
